## Word 操作流程

1. 在桌面版 Word 打开合成稿副本。确认顶部“论文格式检查”功能区提供分析、修复、问题与位置导航按钮；右侧“问题检索”面板只显示搜索框和问题列表。
2. 记录当前文档文件名、路径和 Word 窗口数，再点击“分析当前文档”。确认首次分析直接在当前文档写入黄色标记和可恢复的书签，文件名、路径和窗口数不变；重复分析不累积标记，也不新增文档。不得通过 CLI 预先生成标注稿。
3. 确认三处预设正文错误分别对应宋体、Times New Roman 和 12pt；同一格式项目和目标值合并为一个检索问题，问题卡片保留位置和出现次数。每个合并问题对应一条 Word 原生批注，重复分析不得累积批注。用“上一处/下一处”逐处定位，同一规则的多处位置不能被误报成多个独立问题。
4. **纯鼠标悬停单独测试**：不点击、不拖选正文。将鼠标停在每处黄色标记至少一秒，确认右侧问题检索选中对应卡片，并能看到该卡片的修复建议。每处单独记录；点击/选中后的结果不能记作悬停通过。
5. **检索与反向定位单独测试**：测试普通词及 `类型:`、`期望:`、`实际:`、`位置:`、`状态:`、`来源:` 字段检索。点击检索卡片定位原文；停在黄色标记上反向选择对应卡片。确认没有重复展开另一套问题说明面板。
6. 选择一个可自动修复的问题，执行“修复此项”，在预览中核对格式项目、改前/目标值和涉及位置后确认。确认 Word 没有关闭/重开文档或生成新结果文档；重新分析后仅相关格式变化，问题标记被验证并清除，其他错误仍可定位。用一次 Ctrl+Z 撤销、再用 Ctrl+Y 恢复。
7. 对同一合成稿打开“预览并修复全部”。先取消一次，确认文档无变化；再确认批量修复，检查所有可自动修复项一次性生效，未覆盖项和需人工确认项仍保留。确认批量操作可以整体 Ctrl+Z 撤销、再 Ctrl+Y 恢复；最后由作者按 Ctrl+S 保存当前测试副本。保存前磁盘哈希必须不变。
8. 打开 `clean_sample.docx` 副本并分析，确认显示 0 条问题，不生成黄色标记或 Word 批注。保存并重开此工作副本，再分析一次，确认仍在同一文档中更新。
9. 在一份合成稿中做一个未保存的格式修改后直接分析，检查结果是否反映屏幕上的当前值；记录源文件哈希不变。另开第二个 Word 文档窗口重复分析与定位，确认两窗的侧栏、当前问题和批注不会串位。
10. 在含有原生人工批注的合成稿副本中分析和修复，确认人工批注保留，插件只管理带私有标记的工具批注、黄色标记和书签。
11. 在顶部切换“打开检索/关闭检索”，再用窗格 X 关闭，确认功能区状态同步且其他命令不强制打开列表；检查窄侧栏与多行字段不重叠。对多处问题连续切换并记录响应时间。

## Word 对象模型回归检查（Issue #85）

先编译 VSTO 插件和协议宿主，再从仓库根目录运行以下命令；需要 Windows PowerShell 5.1、Word 桌面版和 Word PIA。脚本只扩展仓库合成夹具，测试产物放在被忽略的 `TestResults/`；它只关闭自己打开的测试文档。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-WordInPlaceRepair.ps1 -Configuration Debug
```

2026-10-22 宿主核查发现，本机 `Word.Application` 的 COM 注册指向 WPS。此前脚本输出不能作为 Microsoft Word 验收证据，原“Word 检查通过”记录已撤回。随后通过 Microsoft Word 桌面界面完成了旧版批注交互专项；该专项记录为历史结果，不能作为当前黄色标记/问题卡片设计的验收结果。

脚本现在会在激活前核对 `Word.Application` 注册的程序必须为 Microsoft `WINWORD.EXE`，激活后再次核对宿主路径；并用完整合成论文检查含表格文档的定位映射、标记恢复和未保存源文件不变。指向 WPS 等其他程序时直接失败，不开始验收。只有 Microsoft Word 宿主的通过结果才可记录为对象模型回归通过；功能区按钮、预览取消、位置导航、检索和纯悬停仍按上表逐项验收。
