## 二、公式、引文、写作中引导、多校样式包谁先谁后

顺序：**公式收尾 → 引文（等访谈）→ 多校样式包（等规则获批）→ 写作期引导不立项**。和「样式优先、公式引文攻坚、不重复造轮」一致。

- **引文**：#119 自己写着「口径待 #110 定」，还写「先做顺序编码制、先覆盖工科」——后半句是假设。文科到底用脚注还是著者-出版年、工科是不是真的只用顺序编码制，访谈前没有答案。所以这条**不是排后面，是不能先做**：口径没定就开工，做完大概率返工。

- **写作期引导**：不立项，见第四节。

「不重复造轮」落在两处：新需求先查 `competitor-reusable-points.md`；`AGENTS.md` 第 8 节已经登记的依赖不重写一遍。

## 三、哪些开源能直接二创（附许可证结论）

许可证是 2026-11-10 从上游仓库元数据 / LICENSE / COPYING / README 原文核的，路径与逐条边界见 `competitor-reusable-points.md`。

| 上游 | 许可证 | 能不能直接二创 |
|---|---|---|
| `AfishInLake/WordFormat` | Apache-2.0 | **能**。可商用、可闭源分发衍生作品；保留版权与许可证声明、标注修改，不传染 |
| `dotnet/Open-XML-SDK` | MIT | **能**，测试工程已在用 |
| `citation-style-language/schema` | MIT | **能** |
| `Unstructured-IO/unstructured` | Apache-2.0 | 能，但中文准确率要自己评测，只借机制 |
| `docling-project/docling` | MIT（模型权重另核） | 能，只在对照位 |
| `citation-style-language/styles` | CC-BY-SA 3.0 | **有条件**。派生样式必须同许可并署名，别把改过的 `.csl` 塞进闭源产物；只读定义当口径参考不算派生 |
| `zotero/zotero` | AGPLv3 | **不嵌**。分发衍生作品要按 AGPL 提供对应源码 |
| `Juris-M/citeproc-js` | CPAL-1.0 或 AGPLv3 | **不嵌**。两个选项都带署名/源码提供义务 |

结论：Apache-2.0 / MIT 那一组可以直接二创，带 ShareAlike 和 AGPL 的只借概念。别把「Zotero 开源」理解成「Zotero 代码能搬」。EndNote 是商业软件，不在开源复用范围。

## 四、写作期引导到底做不做

**做 A，不做 B。B 不立项。**

- A 写完批量修（现状）：写完跑一次命令，一次改到位。现有 13 条命令、`undo` 备份、复诊全在这条路上。
- B 写作期实时引导：Word 里要常驻加载项，误报会烦，每敲一句都要判定，而写的时候本来就最烦被打断；收益没有证据，代价是确定的。

**推翻条件写死**：要推翻 A，必须拿到「有人在写到一半就卡死、最后放弃」的具体例子，否则不立项。访谈里 A/B 是二选一，不开放式提问，也不替受访者选。
这条现在是默认判断，不是访谈结论。11/15 完整版要写清三类学科各选了什么、有没有出现上述具体例子；没有例子就维持 A，把「不问第二遍」这件事定下来。
