## 二、公式、引文、写作中引导、多校样式包谁先谁后

顺序：**公式收尾 → 引文（等访谈）→ 多校样式包（等规则获批）→ 写作期引导不立项**。和「样式优先、公式引文攻坚、不重复造轮」一致。

- **公式**：`#114` 已关闭，`analyze-formula` / `apply-formula-format` 都在，9 份样本、Word 16 实机读过。剩下的只是真实多节论文里的验证，不是攻坚。
- **引文**：#119 自己写着「口径待 #110 定」，还写「先做顺序编码制、先覆盖工科」——后半句是假设。2026-11-11 下午查到南开本科手册原文（P-1，见 `interview-notes-2026-11-11.md`）：**注释一律采用页下注，参照《中国社会科学编排规范》，序号①②③、每页独立编号**。也就是说，在南开本科口径上这个假设被推翻，体例应当按页下注来，而不是顺序编码制。但只推翻了一半：研究生 2026 版 R14 只规定参考文献段的字体字号行距，没规定注释体例；文科那位受访者（`文-1`）也只说了用 Zotero，没答「最常出错哪几项」。所以结论改成：**体例有依据了，频次还没有，仍然不是现在能开工的活**。11-11 傍晚再用 D2 §9 修正一次口径：同一份规范里「参考文献可采用顺序编码制，也可按著者-出版年制，建议按顺序编码制」与「人文社科可采用页下注」是并存的，所以将来若做，是两层检查——参考文献段按 GB/T 7714、注释体例按所在培养单位，不做体例转换。这条 issue 已于 2026-11-11 撤回（当时无人认领，下周原样重发），重发时把口径句改成「参考文献按 GB/T 7714，注释按培养单位；南开本科要求页下注，研究生待补」。
- **多校样式包**：`rules/nku-graduate/colleges/` 还是空目录，而南开自己这套 `meta.status` 仍是 draft。一套没获批的规则铺不出多套，先等规则负责人复核。能借的只是 WordFormat 领域包自动发现的组织方式（Apache-2.0）。
- **写作期引导**：不立项，见第四节。

「不重复造轮」落在两处：新需求先查 `competitor-reusable-points.md`；`AGENTS.md` 第 8 节已经登记的依赖不重写一遍。

## 三、哪些开源能直接二创（附许可证结论）

许可证是 2026-11-10 从上游仓库元数据 / LICENSE / COPYING / README 原文核的，路径与逐条边界见 `competitor-reusable-points.md`。

| 上游 | 许可证 | 能不能直接二创 |
|---|---|---|
| `AfishInLake/WordFormat` | Apache-2.0 | **能**。可商用、可闭源分发衍生作品；保留版权与许可证声明、标注修改，不传染 |
| `dotnet/Open-XML-SDK` | MIT | **能**，测试工程已在用 |
| `citation-style-language/schema` | MIT | **能** |
| `Unstructured-IO/unstructured` | Apache-2.0 | 能，但中文准确率要自己评测，只借机制 |
| `docling-project/docling` | MIT（模型权重另核） | 能，只在对照位 |
| `citation-style-language/styles` | CC-BY-SA 3.0 | **有条件**。派生样式必须同许可并署名，别把改过的 `.csl` 塞进闭源产物；只读定义当口径参考不算派生 |
| `zotero/zotero` | AGPLv3 | **不嵌**。分发衍生作品要按 AGPL 提供对应源码 |
| `Juris-M/citeproc-js` | CPAL-1.0 或 AGPLv3 | **不嵌**。两个选项都带署名/源码提供义务 |

结论：Apache-2.0 / MIT 那一组可以直接二创，带 ShareAlike 和 AGPL 的只借概念。别把「Zotero 开源」理解成「Zotero 代码能搬」。EndNote 是商业软件，不在开源复用范围。

## 四、写作期引导到底做不做

**做 A，不做 B。B 不立项。**

- A 写完批量修（现状）：写完跑一次命令，一次改到位。现有 13 条命令、`undo` 备份、复诊全在这条路上。
- B 写作期实时引导：Word 里要常驻加载项，误报会烦，每敲一句都要判定，而写的时候本来就最烦被打断；收益没有证据，代价是确定的。

**推翻条件写死**：要推翻 A，必须拿到「有人在写到一半就卡死、最后放弃」的具体例子，否则不立项。访谈里 A/B 是二选一，不开放式提问，也不替受访者选。
这条现在是默认判断，不是访谈结论。11/15 完整版要写清三类学科各选了什么、有没有出现上述具体例子；没有例子就维持 A，把「不问第二遍」这件事定下来。

- 三类学科访谈：**工科 0 / 1、理科 0 / 1、文科 1 人已回收但四问未答**（2026-11-11 下午，共 4 份聊天调研，其中 1 份本人还没写过论文，不计入）。出现频次仍全空。所以 #119 的「工科用顺序编码制」仍是假设，且在南开**本科**口径上已被手册原文推翻（注释要求页下注）。完整名单见 `requirements-list.md` 第 3 节，逐条记录见 `interview-notes-2026-11-11.md`。
- 11-11 傍晚补了一层**规范取证**（`discipline-specs-2026-11-11.md`）：D1 国科大工程科学分会要求（四个工科学科）、D2 中南大学研究生规范、D3 南开本科手册、G1 GB/T 3102.11。它让需求清单与矩阵的「学科」列填实，也让 N07 的口径从「选一种体例」改成两层——参考文献段按 GB/T 7714，注释体例按培养单位（D2 §9 顺序编码制是建议、页下注是人文社科选项；D3 本科一律页下注）。**但它不产生频次，也不改任何一条结论**：这一节第一句话里的 0 / 1、1 / 3 与 A/B 0 / 3 都还成立。

- 结论里凡写「已交付」的，都能追到合并的 PR 和实跑报告；凡写「待验证」「等访谈」的，没有拿推测填。
- 周会上讲五分钟，之后每周日更新一次。没有新访谈的周次只记「本周无新增访谈，结论未改」，不为显得有进展去改优先级。
