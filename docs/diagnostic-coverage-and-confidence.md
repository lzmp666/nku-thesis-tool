# 诊断范围与正确性依据

## 规则如何对应论文规范

诊断遵循一条可追踪链：官方规范原文及定位 → 覆盖矩阵条目 → 经负责人批准的规则定义 → 规则 ID → 分析器实现 → 正确/错误/未知样例 → 修复预览与复查。覆盖矩阵中的 `M26-*` 是来源追踪号；`NKU-REQ-*` 目前只是候选标识。当前 2026 版正文规则仍标记为 `draft`，不能宣称为正式的南开大学完整合规检查。

当前实现的草案范围仅有正文中文字体、正文英文/西文字体和正文字号（规则候选 `NKU-REQ-042` 至 `NKU-REQ-044`）。分析器根据 Word OOXML 段落、文本片段和有效格式值定位问题；仅对已确认正文范围使用这些要求。段落位置会将表格单元格段落纳入文档顺序索引，以避免出现表格后定位错位，但表格单元格自身被排除出正文规则。标题、摘要、目录、题注、参考文献、附录、文本框、脚注和公式等不套用这三项正文规则。

## 中文与英文的识别

文本按 Unicode 字符范围识别汉字与拉丁字母。汉字文本只比较东亚字体槽 `eastAsia`；含拉丁字母的文本比较 `ascii` 与 `hAnsi`；字号对范围内非空文本检查。若需要的字体槽/样式继承结果无法解析，结果是“未知/未覆盖”，不会当作通过。当前识别器的保证仅限其明确列出的汉字和拉丁字母范围；希腊文、西里尔文、阿拉伯文、复杂文字脚本、数学符号以及字体回退渲染不在拉丁字体规则保证内。

## 如何建立对正确性的信心

1. 规则值来自可定位的规范句子，并记录版本、章节/表格、来源和审核状态；未明确的要求保持未覆盖。
2. 对 OOXML 的样式继承、直接格式、主题/未知值和多节文档分别测试；识别不到值时拒绝给出通过结论。
3. 每次修复先检查稳定位置、原值和规则，再展示改前/目标预览；用户确认后只更新当前 Word 文档，不自动保存。
4. 修复完成后重新分析。只有相应诊断消失，才可说该位置已按当前规则通过；这不能证明未覆盖项或整篇论文合规。
5. 用合成论文涵盖中文、英文、图、表、公式、参考文献和附录，另外运行单元/集成测试。桌面 Word 版本、字体安装和最终分页仍要在目标 Word 环境验收。

## 图、表与图片的真实覆盖范围

表格存在本身不再阻止安全读取正文；其单元格格式仍不会套用正文宋体/Times New Roman/12 pt 要求，也没有自动表格样式修复。题注将从正文规则中排除，但图题/表题规定（如字体、字号、上下位置）尚未实现为可诊断、可修复规则。嵌入图片的分辨率、清晰度、自明性、裁剪和浮动环绕需要内容或视觉判断，当前不会自动判定。合成测试论文包含图表，是为了验证解析、索引不偏移、文档不破坏和未支持范围明确，而不是声称图表格式已合规验证。
