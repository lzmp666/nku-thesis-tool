# 行距（Line Spacing）规则说明

> **状态**：草案（结构样本阶段，待规范审核）
> **对应 issue**：#4「行距不能只按一个数值判断」
> **允许目录**：`docs/rule-notes/`
> **本文目标**：核验行距的**倍数、固定值、最小值**三种模式及**段落范围**，列出歧义与需 RFC 字段。行距不能只按一个数值判断——同一个数值在不同 `w:lineRule` 下含义完全不同。

---

## 1. 出处

| 出处 | 内容 |
|---|---|
| ECMA-376 Part 1 §17.3.1.33（`w:spacing`） | `w:line` + `w:lineRule` 的权威定义与单位 |
| ECMA-376 Part 1 §17.3.1.26（`w:pPr`） | 段落属性与样式继承位置 |
| Microsoft Word 桌面版 UI（段落对话框 → 行距） | 用户可设置：单倍 / 1.5 倍 / 2 倍 / 最小值 / 固定值 / 多倍行距 |
| Word 在线文档《调整行距》 | 各模式对文本文本块高度的视觉影响说明 |
| 本项目格式规范（NKU 论文要求） | **待规范审核**，见 §8 RFC 候选第 1 条 |

> 注意：本文中"Word 行为"以 Microsoft Word 2016/2019/365（Windows）为参照；WPS Office 大体一致但存在渲染差异（见 §7 歧义 8）。

## 2. OOXML 表达模型

行距存储在段落属性 `w:pPr` 的 `w:spacing` 元素上：

```xml
<w:pPr>
  <w:spacing w:line="360" w:lineRule="auto"/>
</w:pPr>
```

- `w:line`：数值，**含义随 `w:lineRule` 变化**（这是"不能只按一个数值判断"的根源）；
- `w:lineRule`：`auto`（倍数）/ `exact`（固定值）/ `atLeast`（最小值）；
- `w:lineRule` 省略但 `w:line` 存在时，按 ECMA-376 默认为 `auto`（实现建议：遇到省略时先显式归一化为 `auto` 再比较，避免歧义）；
- `w:spacing` 还同时承载段前/段后（`w:before` / `w:after`）与行距，**两者是不同字段**，见 §7 歧义 6。

## 3. 三种模式详解

### 3.1 倍数（`lineRule="auto"`）

| 项 | 说明 |
|---|---|
| Word UI 名称 | 单倍行距 / 1.5 倍行距 / 2 倍行距 / 多倍行距（需填"设置值"） |
| `w:line` 单位 | **240 分之一行**：`line / 240 = 倍数` |
| 常见值 | 240=单倍，360=1.5 倍，480=2 倍，300=1.25 倍 |
| 基准 | 行高随行内最大字体的固有行高缩放（字体度量决定，非固定磅值） |

示例 XML（1.5 倍行距）：

```xml
<w:spacing w:line="360" w:lineRule="auto"/>
```

**边界**：

- 倍数是**相对值**：同一 1.5 倍，宋体小四与黑体三号的绝对行高不同（见 §7 歧义 2）；
- Word UI"单倍行距"即 `line="240" lineRule="auto"`，与"多倍行距填 1"完全等价；
- 倍数可为小数（UI 允许 0.5–5 之类输入），`line` 为整数 240 分制，1.25 倍 = 300 无精度损失，但 UI 输入超过 3 位小数会被 Word 舍入。

### 3.2 固定值（`lineRule="exact"`）

| 项 | 说明 |
|---|---|
| Word UI 名称 | 固定值（需填磅值） |
| `w:line` 单位 | **20 分之一磅（twip）**：`line / 20 = 磅` |
| 常见值 | 400=20 磅，440=22 磅，500=25 磅 |
| 基准 | 行高恒为该磅值，与字号、字体无关 |

示例 XML（固定值 20 磅）：

```xml
<w:spacing w:line="400" w:lineRule="exact"/>
```

**边界**：

- **裁剪**：当固定值小于行内字符的固有高度时，Word 会裁剪字符显示（中文尤其明显，字被削顶/削底）。工具应能提示"固定值 N 磅小于字号 M 磅的常见行高"这类风险（是否提示 → RFC 候选 4）；
- 固定值不随字体缩放，正文与脚注、表格若共用会视觉失衡。

### 3.3 最小值（`lineRule="atLeast"`）

| 项 | 说明 |
|---|---|
| Word UI 名称 | 最小值（需填磅值） |
| `w:line` 单位 | **20 分之一磅（twip）**：`line / 20 = 磅` |
| 常见值 | 同固定值 |
| 基准 | 行高 = max(声明的最小值, 行内实际需要高度)；实际内容更高时自动撑开 |

示例 XML（最小值 20 磅）：

```xml
<w:spacing w:line="400" w:lineRule="atLeast"/>
```

**边界**：

- 当内容固有高度 ≤ 声明值时，视觉与固定值相同；当声明值 ≤ 单倍固有行高时，视觉与单倍行距相同——**数值合法但视觉可能"看不出"**（见 §7 歧义 5）；
- "最小值"与"固定值"的 `w:line` 单位相同，**仅 `w:lineRule` 一个词之差**，解析时必须同时读取两个字段。

### 3.4 单位换算速查

| 规范表述 | XML 写法 |
|---|---|
| 单倍行距 | `w:line="240" w:lineRule="auto"` |
| 1.5 倍行距 | `w:line="360" w:lineRule="auto"` |
| 2 倍行距 | `w:line="480" w:lineRule="auto"` |
| 固定值 20 磅 | `w:line="400" w:lineRule="exact"` |
| 最小值 22 磅 | `w:line="440" w:lineRule="atLeast"` |
| （倍数）1.25 倍 | `w:line="300" w:lineRule="auto"` |

换算公式：倍数 × 240 = `w:line`（auto）；磅值 × 20 = `w:line`（exact / atLeast）。

## 4. 段落范围与继承链

### 4.1 有效值的解析顺序（从高到低）

1. 段落**直接格式** `w:pPr/w:spacing`（若存在 `w:line`）；
2. 段落引用的**段落样式**（含 `w:basedOn` 链条逐级向上）；
3. `w:docDefaults/w:pPrDefault`；
4. 全不存在 → Word 应用默认单倍行距（等价 auto 240）。

> 实现要点：检查器必须解析完整继承链得到**有效行距**，而不是只看直接格式；issue #5 的 `style_override_*` 样本即针对此场景。

### 4.2 规则适用的段落范围

行距规则（如"正文 1.5 倍行距"）通常只约束**特定范围**的段落。本文按 NKU 论文常见结构列出范围分类，供规范审核时勾选：

| 范围 | 是否纳入行距校验 | 说明 |
|---|---|---|
| 正文段落 | ✅ 默认纳入 | 主要校验对象 |
| 各级标题 | ❓ RFC 候选 5 | 论文规范常对标题另有行距/段前段后要求 |
| 表格内段落 | ❓ RFC 候选 5 | 常被豁免（表格需要紧凑行距） |
| 图表题注 | ❓ RFC 候选 5 | 常为单倍 |
| 页眉 / 页脚 / 页码 | ❓ RFC 候选 5 | 通常不校验 |
| 脚注 / 尾注 | ❓ RFC 候选 5 | 常为单倍 |
| 目录（TOC 域生成段落） | ❓ RFC 候选 5 | 生成内容，是否校验待定 |
| 文本框 / `w:txbxContent` | ❓ RFC 候选 5 | 浮动内容，建议豁免 |
| 空段落 | ❓ RFC 候选 5 | 空段落同样携带行距，影响版面；是否单独提示待定 |

## 5. 示例（与测试样本对应）

`tests/fixtures/synthetic/line_spacing_wrong.docx`：

- 场景：正文应为 1.5 倍（`auto` 360），样本中正文段全部为单倍（`auto` 240）；
- 预期：检查器读取每段有效行距 → `lineRule=auto, line=240` → 倍数 1.0 ≠ 1.5 → 报错并定位段落；
- 该样本仅覆盖 **auto 模式 + 直接格式**；`exact` / `atLeast` 模式、样式级行距、网格对齐场景**尚无样本**，见 §6 边界与 §9 建议补充。

## 6. 边界情形汇总

1. `w:line` 存在但 `w:lineRule` 省略 → 按 `auto` 归一化后再判断；
2. `w:lineRule` 存在但 `w:line` 省略 → 无效声明，Word 忽略行距设置，检查器应按"未设置"处理（继承链继续向上）；
3. `w:line="0"` → 非法值，Word 忽略；
4. 同一文档内正文混用 auto 与 exact（不同段落不同模式）→ 逐段判断，不要求全文统一模式（除非规范另有说明）；
5. `docDefaults` 定义了行距但段落样式未覆盖 → 继承链仍生效，需解析到 docDefaults；
6. **文档网格**（`w:sectPr/w:docGrid` 定义 `w:linePitch`）启用且段落 `w:snapToGrid` 未关闭时，实际行高对齐到网格，声明行距被网格覆盖（见 §7 歧义 3）；
7. 段前/段后（`w:before`/`w:after`）与行距同在 `w:spacing` 元素上，解析时不能"读到 spacing 就当行距"。

## 7. 已知歧义

1. **规范表述歧义**：「1.5 倍行距」按字面应指 `auto 360`；但若规范本意是"固定行距约 20 磅"，两者数值不同、视觉效果也可能不同。**数值本身无法消歧，必须由规范审核确认意图**。
2. **倍数 ≠ 绝对行高**：`auto` 的行高基准是行内最大字体的固有行高（含字体度量的 ascent/descent/lineGap）。同一 `auto 360`，不同字体、不同字号的绝对行高不同。检查器只能校验**声明值**，无法保证**视觉行高**一致。
3. **文档网格交互**：启用 `docGrid`（Word 中文模板常见"指定行网格"）时，`snapToGrid`（默认开）使实际行高取网格 `linePitch`，行距声明被部分覆盖。工具若只读 `w:spacing` 会与所见不符。
4. **固定值裁剪**：`exact` 值小于字符固有高度时文字被裁剪，"合法但难看"，是否提示属产品决策。
5. **最小值的视觉不可见性**：`atLeast` 声明值 ≤ 内容固有高度时视觉等同单倍；数值与视觉脱节，人工验收与机器校验可能给出不同结论。
6. **段前段后混淆**：用户常把"段前/段后 0.5 行"当成行距设置；两者是 `w:spacing` 的不同属性。规范必须明确是否同时校验段前段后。
7. **范围未定**：§4.2 表中所有 ❓ 项——标题、表格、题注、页眉页脚、脚注、目录、文本框、空段落是否校验，规范未定。
8. **WPS/Word 渲染差异**：WPS 对 `atLeast` 的撑开行为、网格对齐的实现与 Word 存在细微差异；同一文件两边打开视觉行高可能不同。校验应以 XML 声明值为准，视觉差异只作人工复核参考。
9. **"单倍"与"未设置"的等价性**：显式 `auto 240` 与完全未声明（继承默认单倍）数值等价、视觉等价，但语义不同（一个是有意设置，一个是默认值）。是否区分报告待定。

## 8. RFC 候选（无法仅靠本文表达、需规范/架构决策）

| # | RFC 议题 | 需要的决策 |
|---|---|---|
| 1 | 正文行距的规范意图 | 「1.5 倍」= `auto 360`，还是固定磅值（多少磅）？规范审核必须给出唯一定义 |
| 2 | 视觉行高是否纳入验收 | 检查器只校验声明值（推荐），还是引入渲染后视觉行高（成本高，需另立方案） |
| 3 | 文档网格（docGrid/snapToGrid）处理策略 | 忽略网格只看声明 / 读取网格并按实际行高判断 / 检测到网格即给出提示 |
| 4 | `exact` 小于字号时的裁剪警告 | 是否提示、阈值如何定 |
| 5 | 行距校验的段落范围 | §4.2 表逐项勾选：纳入 / 豁免 / 单独规范值 |
| 6 | 段前/段后是否与行距一并校验 | 若是，规范值与单位（行 or 磅）需同步给出 |
| 7 | `atLeast` 的语义校验级别 | 仅校验声明值 ≥/=/≤ 规范值，还是需要计算实际行高判断"视觉达标" |
| 8 | `auto 240`（显式单倍）与未设置是否区分报告 | 报告粒度问题 |
