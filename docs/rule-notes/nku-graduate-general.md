## 2. 正文范围（哪些部分纳入字体/字号检测）

规范第 4 章对各部分分别规定了排版要求，即"正文范围"应按**论文组成部件**划分，而不是单一"正文"概念。2025 版中给出明确字体/字号规定的部件如下（条款项号均为 2025 版）：

| 部件 | 条款 | 是否 v1 建议检测 |
|---|---|---|
| 页面设置（纸张/页边距/页眉页脚边距） | 4.1 表 4.1 | ✅（节属性，检测成本低） |
| 篇眉、页码 | 4.1 表 4.1 + 3.4 | ✅ |
| 中文封面 / 题名页 | 4.2 表 4.2、4.4 表 4.3 | ❌ 建议不检（封面已有固定版式，"只须提供有关内容"） |
| 书脊 | 4.3 | ❌ 不检（印刷品属性，docx 中通常不存在） |
| 中文摘要 | 4.5 表 4.4 | ✅ |
| 英文摘要（Abstract） | 4.5 表 4.4 | ✅ |
| 目录 | 4.6 表 4.5 | ✅ |
| 正文：章标题 / 一~三级标题 / 段落文字 | 4.7 表 4.6 | ✅（v1 核心） |
| 正文：图序图题 / 表序表题 / 表达式 | 4.7 表 4.6 | ⚠️ 可选（依赖图表识别，建议 v1 后） |
| 符号注释表 / 参考文献 / 附录 / 勘误页 / 致谢 / 个人简历等 | 4.8 表 4.7 | ⚠️ 部分（参考文献、附录可检；致谢字体为**仿宋**，易被误报，见 A5） |

部件在 docx 中的**识别方式**（摘要从哪段开始、目录到哪里结束）规范未规定机器可依据的标记，见 RFC-2。

## 4. 字体脚本（font script）的核验

规范原文的表述模式是"中文字体 + '英文用×××字体'"，**没有使用 OOXML 术语**。OOXML 的 run 级字体分四个槽位：`w:ascii` / `w:hAnsi` / `w:eastAsia` / `w:cs`。映射关系是**实现约定而非官方条文**：

| 规范表述 | 建议映射 | 依据 |
|---|---|---|
| 宋体12磅（中文） | `w:eastAsia = 宋体` | 惯例映射 |
| 英文用 Times New Roman | `w:ascii = Times New Roman`（且 `w:hAnsi = Times New Roman`） | 惯例映射 |
| Abstract 用 Arial | 同上槽位 | 条文本身 |

该映射属于解释性决定 → **RFC-1**（v1 契约必须先定义，否则"字体检测"无法实现）。另注意：
- 原文写"**英文**"，未提数字、拉丁符号、其他西文——数字（如页码、表达式序号）按哪个字体，条文未明说（规范对表达式序号单独规定 TNR，可作旁证）→ A4。
- `w:cs`（复杂文种）条文完全未涉及，不建议 v1 检测。
- "宋体/黑体/仿宋"是字体**中文名**，docx 中可能写作 `SimSun`/`SimHei`/`FangSong` 或主题字体引用 → 字符串匹配策略需 RFC-5。

## 5. 字号表述的双重体系

规范通篇使用"**磅值（或中文字号名）**"双写：12磅（或小四）、10.5磅（或五号）、16磅（或三号）、14磅（或四号）、22磅（或二号）、18磅（或小二）。**OOXML 中只有半磅值（`w:sz`，单位 half-point）**，因此检查器统一按磅值断言，中文字号名仅作文档说明。已知坑：
- **13 磅无中文字号名**（R9），Word"字号"下拉框显示为"13"；
- 中文字号与磅值的对应（五号=10.5、小四=12、四号=14、小三=15、三号=16、小二=18、二号=22）是排版惯例，**规范未定义换算表**，检查器不得依赖字号名做断言 → RFC-5 附带。
- 表格内文字、脚注字号：**规范未规定** → T3，不得猜测。

## 6. 歧义与待确认项

### 待确认（T）
- **T1（部分完成）**：2026 版第 4.7 节表 4.6 正文段落字体/字号已核对（#43，S2026）；其余章节（页面设置/标题/摘要/目录/参考文献/附录/致谢等）仍待 2026 版全文逐条比对。
- **T2**：研究生院官方页面（S3）仍挂 2020 修订版，2025/2026 版无研究生院官方直链——需向研究生院/学位办确认现行版原文获取渠道。
- **T3**：表格单元格内文字、脚注、图片内文字的字体字号**规范未规定**——v1 不得虚构规则。
- **T4**："或五号"等括号表述是"等价别名"还是"任选其一"：Word 中磅与字号名本就是同一值的双写，按等价处理，但需负责人确认检测口径。
- **T5**：页边距"页眉、页脚3.0cm"指页眉/页脚距边界距离（Word"页眉距顶端/页脚距底端"），需确认与 Word UI 对应关系后写入断言。
- **T6**：目录条目"各章目录/一级标题目录/二级标题目录"三级字号（四号/小四/五号）在自动生成目录（TOC 域）场景下如何检测——TOC 域内容由样式生成，检测对象应是 TOC1/TOC2/TOC3 样式还是渲染结果，需 RFC。

### 歧义（A）
- **A1**："固定值行距20磅（段落中有数学表达式时，可根据表达需要设置该段的行距）"——豁免条件无法机器判定（何为"数学表达式"段落），见 RFC-4；详细行距模式分析见 `line-spacing.md`。
- **A2**：章标题"加粗居左……模式二加粗居中"——对齐取决于编号模式，检查器需先判定模式（与 `headings.md` 的双模式冲突清单联动）。
- **A3**："章序号与章题目间空一个汉字符"——"空一个汉字符宽度"在 OOXML 中可能是空格、全角空格或制表位，条文未规定字符 → RFC。
- **A4**："英文用 Times New Roman"是否涵盖数字与其他西文字符未明说。
- **A5**：致谢用仿宋（R17）与正文宋体（R11）不同，全局字体断言会误报——范围必须按部件切片。
- **A6**：英文摘要标题用 Arial（R5）与英文摘要正文 Times New Roman 并存。

## 7. RFC 候选（表达不足，需先提 RFC 再实现）

| ID | 主题 | 要点 |
|---|---|---|
| RFC-1 | 字体脚本映射契约 | 规范"中文/英文"表述 ↔ `w:ascii`/`w:hAnsi`/`w:eastAsia` 槽位映射；是否检 `w:cs` |
| RFC-2 | 部件范围识别 | 如何从 docx 结构界定摘要/目录/正文/参考文献/附录/致谢的分界（样式名？分节符？标题大纲级别？） |
| RFC-3 | 字体名匹配 | `宋体` vs `SimSun` vs 主题字体引用（`majorEastAsia`）的等价判定表 |
| RFC-4 | 行距豁免策略 | 含数学表达式段落的白名单/启发式判定；exact 20pt 的容差（0.5pt？） |
| RFC-5 | 数值断言口径 | 磅值唯一化；容差定义；`w:sz`（half-point）换算；13pt 等无字号名条目 |
| RFC-6 | 封面/固定版式豁免 | 封面、题名页、匿名评阅封面是否完全跳过 |
