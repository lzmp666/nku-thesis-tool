# 文档级版式检查：查什么、依据在哪、为什么这么判

对应 Issue #112。第一档（11/22）实现 `analyze-document`，覆盖纸张、页边距、页眉页脚距离、
装订线、页眉页脚有无、页码域、页码格式、目录、疑似空白页；第二档（11/29）补上 R2/R3 的
篇眉与页码字体字号居中、只动 `sectPr` 的自动修复、`analyze --scope`，并按 Word 实机结果
把空白页的判定拆成两种。

本文只记录判断口径和实测依据，规范值本身以 `rules/nku-graduate/general.yaml` 为准，
不在这里复制一遍。Word 16 实机核验的原始读数与截图见
[word-112-acceptance.md](../research/word-112-acceptance.md)。

## 三处判断上的取舍

### 页眉和页码按全文判，不按节判

实测 Word 16 保存文档时，会为**每一节**建好 `default` / `even` / `first` 三组页眉页脚引用，
即使内容为空。而规范说「篇眉从中文摘要开始」——封面本来就没有页眉。

按节判「本节页眉为空」，等于把每篇合格论文都报一遍。第一次用就被报错的工具，后面说什么都没人信。
所以只在**全文都没有页眉内容**时报一条，并在 `Current` 里列出是哪些节为空，用户自己判断。

页码同理：只要全文有一处 PAGE 域就算有页码。某一节没有页脚不当问题报——封面节经常不要页码。

### 页码格式只在「多节且全相同」时报

R3 要求前置部分用大写罗马、正文用阿拉伯。但判断「哪一节是前置部分」需要识别文档结构，
XML 层面判不准（摘要、目录、正文的切换没有标记）。

所以只报一种确定的情形：文档有 ≥2 节，且所有节的 `fmt` 完全一样——这说明压根没做区分。
单节文档不报，单节判不出分界，硬判就是瞎猜。这项在「未检查」里也写明了。

### 页码域要排除 NUMPAGES

`NUMPAGES` 是总页数，不是页码。只看「有没有 PAGE 字样」的实现，会把页脚里
「第 X 页 共 Y 页 共 10 页」的文档判成有页码。用 `(?<!\w)PAGE(?!\w)` 匹配，前后不能紧邻字母。
有单测守这条。

## 容差不是可选项

实测 Word 16 存出来的数字和教科书上写的对不上：

| 项 | 常见写法 | Word 16 实际 |
| --- | --- | --- |
| A4 纸张 | 11906 × 16838 twips | 11907 × 16839 |
| 3.8cm | 2155 twips | 2154 |

差 1 twip 是取整方式不同。写死 `== 11906` 的检查，会把 Word 自己排的合规文档判成不合规。
所以所有长度比较走 0.1cm 容差（≈57 twips），既吸收取整差，又不会把 1.27cm 这种真错误放过。

**修复器也必须用同一个容差**。第一版 `DocumentFormatter` 无条件写自己换算出来的 2154，
结果把 2155 的合规样本全改了一遍，还和检查器「2155 没问题」的说法打架。现在先按
0.1cm 判一次，超差才写；测试和修复认同同一批数字、同一个容差。

## 节的顺序

`CollectSectionProperties` 按文档顺序取：先扫所有段落属性里的 `sectPr`（分节符），
再补 `body` 末尾那个（最后一节）。顺序错了，每一项检查都会标到错误的节上。

没有 `body` 级 `sectPr` 的文档（不规范但存在），用最后一个段落里的 `sectPr` 兜底。
不补这一条会少一节，页面检查就漏了整节。修复器复用同一个方法，避免「检查说 3 节、
修复只改 2 节」。

## 第二档：样式链怎么展开

R2/R3 的字体字号经常不在页眉页脚段落上，而是写在 `styles.xml` 的 `Header` / `Footer` 样式里。
`PartFormatReader` 按 `run 的 rPr → 段落 pStyle → basedOn → docDefaults` 逐层找值，
带环防护，坏文档不该把检查器挂死。

三条口径：

1. **按属性分别判**，不搞「整份部件有效/无效」一刀切。`styles.xml` 缺失但 run 上显式写了
   rPr、段落显式写了 jc，这些值照样能判；没写又没链可查的，才标「未判定」。
2. 对齐缺省为左对齐只在**样式链完整**时可信。链断了看不到「页眉」样式是不是居中，
   这时没写 jc 就标未判定，不拿默认值凑问题数。
3. 同一段落里多个 run 格式不一致时，取谁都不代表这一段，整段标未判定，需人工看。

判不出来的维度会逐条写进报告末尾「本次未检查」，并在头部打印「完整判定 N / M 个文字段落」。
`document_no_styles_part.docx` 是专门造的对照样本：0 条问题、完整判定 0/2，
报告明确写「不能据此说文档合规」。

字体验别名（宋体 / SimSun、Times New Roman / 去空格写法），字号只认 `w:sz/@val` 的半点值
（10.5 磅 = 21）。`w:szCs` 是复杂文种，不判。

全西文篇眉按 R2「Abstract 部分用 Times New Roman 10.5 磅」判，含中文的按「宋体」判。
XML 层面认不出哪一节是 Abstract，只能按文字是否全为西文近似，这条在「未检查」里也写明了。

## 第二档：自动修复的边界

`apply-document-format` 只写 `sectPr` 下 `pgSz` / `pgMar` 的属性：

- 纸张宽高、上下左右边距、页眉页脚距、装订线，共 9 个属性；
- 不新增、不删除 XML 元素。`pgSz` / `pgMar` 整个缺失时记「没自动改」并说明原因
  （`sectPr` 子元素有 schema 顺序，乱插会让 Word 拒绝打开）；
- 不动 `headerReference` / `footerReference` / `pgNumType` / `titlePg` / 分节类型；
- 不动正文、页眉页脚部件、`settings.xml`。

按原顺序重建 ZIP 包，除 `word/document.xml` 外所有条目原样复制字节，条目顺序与时间戳也保持一致
——不带时间戳的话第二次跑会因为 ZIP 元数据不同而逐字节不同，幂等性就验不了。

目录、页码、空白页、页眉页脚字体字号、奇偶页不同一律只报告不改，命令输出里逐条列出来。
issue 把修复分成了两类，误删内容或改坏域的风险担不起。

`undo` 接的是仓库统一的备份机制，实测回滚后与原件逐字节相同。

## 第二档：空白页的实机修正

第一档把「空段落里带分页符」直接叫疑似空白页。Word 16 双页视图实测发现这个说法偏松：

| 样本 | Word 实际页数 | 第 2 页 |
| --- | --- | --- |
| `document_blank_page.docx`（单个空段落 + 分页符） | 2 | 有正文第二段 |
| `document_true_blank_page.docx`（连续两个空段落 + 各一个分页符） | 3 | 无正文，整页空白 |

所以 D10 现在分两种报法，措辞不混用：单个的报「疑似空白页」并在 `当前` 里写明
「只会多一页，不等于整页空白」；连续的报「连续分页符造成整页空白」，给出删多余空段落的操作。
两者都属惯例项，规范里没有空白页条款，不因为实机能验就升格成规范项。

## 未覆盖

- 页眉横线：规范未作规定，不查（见开头）。
- 页眉是否为 Abstract 部分：按文字是否全为西文近似，判错的要人工确认。
- 正文从第一章起编阿拉伯数字：要判断哪一节是「第一章」，靠 XML 判不准。
- 奇偶页是否真的「内容相同」：只查了开关，没比对奇偶页眉文字。
- 空白页的完整判定：段后间距、表格跨页导致的空白要真实分页才成立，XML 层面算不出来。
- 页面方向与装订线位置：规范未作规定，不查。

## 与参考实现的对照

`AfishInLake/WordFormat` 的 `src/wordformat/header_footer.py`（Apache-2.0）覆盖了同类检查项。
有三处写法值得记：

1. `PAGE` 域的正则排除了 `NUMPAGES`，本实现照此处理。
2. 它把 `page_setup` 检查做成 opt-in（配置里写了才校验），理由是各校边距差异大。我们不同：
   南开规范明确规定了数值，所以默认必查。
3. 它会对页眉的段落标记字体也做检查。本实现没做——页眉段落标记字体不影响正文字形，
   而样式链未展开时容易误报。

代码为独立编写，未复制其实现。
