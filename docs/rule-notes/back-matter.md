# 尾注部件格式检查口径（R14–R17）

> 对应规则：`rules/nku-graduate/general.yaml` 的 R14、R15、R16、R17（4.8 表4.7）。
> 规则状态：**draft**（来源 S1 的 2025 版条文，待 2026 版全文核验），报告会提示需人工确认。
> 实现：`src/ThesisEngine.Core/BackMatterFormatAnalyzer.cs`；命令：`analyze-back-matter`（只查不改）。

## 1. 条款值与检查维度

| 部件 | 规则 | 依据原文要点 | 本命令检查的维度 |
| --- | --- | --- | --- |
| 参考文献 | R14 | 标题同各章标题；宋体 10.5 磅（五号），英文 Times New Roman 10.5 磅，固定值行距 16 磅，段前段后 0 磅 | 正文中文字体、西文字体、字号、行距与段距 |
| 附录 | R15 | 宋体 12 磅（小四），英文 Times New Roman 12 磅，两端对齐，段落首行左缩进 2 汉字符，固定值行距 20 磅（含数学表达式时可按表达需要调整），段前后 0 磅 | 正文四项 + 对齐、首行缩进 |
| 符号/标志/缩略语注释表；个人简历与成果 | R16 | 宋体 / Times New Roman 10.5 磅，固定值行距 16 磅，段前段后 0 磅 | 正文中文字体、西文字体、字号、行距与段距 |
| 勘误页、致谢 | R17 | 标题同各章标题；仿宋 12 磅（小四），固定值行距 16 磅，段前段后 0 磅 | 正文中文字体、字号、行距与段距 |

问题码按部件连续编号：R14 为 B1–B4，R15 为 B5–B10，R16 为 B11–B14，R17 为 B15–B17。
每个码固定对应一个维度，不因部件内是否另有维度而改变。

## 2. 明确不判的对象

- **部件标题**：条文写「同各章标题（R7）」，由标题检查负责；本命令只判正文段落，标题格式在报告里明确列为未判定。
- **参考文献著录内容与引用一致性**：字号字体之外的内容（GB/T 7714 字段、编号一一对应）属另一条工作（#152），本命令不碰。
- **部件边界的语义判断**：按标题文字定位（参考文献 / 主要参考文献 / References、附录 A 或附录 A：标题、符号说明 / 个人简历、致谢 / Acknowledgements）。定位不到的部件列入「未识别」，不按合规处理。
- **公式段的例外**：条文允许附录中含数学表达式的段落按表达需要调整行距。通过 OOXML `m:oMath` / `m:oMathPara` 识别，只豁免行距规则与值；该段仍须满足字体、字号、对齐、首行缩进与段前后 0 磅。是否真的因为公式才调整行距，机器判不了，需在报告里人工确认。
- **附录 A/B 子标题**：同一部件的第二处及以后标题不算正文段落，避免拿标题格式误报正文问题。
- **纯西文段落的 eastAsia 字体槽**：条款的「中文宋体」对纯西文段不适用，不报问题；西文槽按 Times New Roman 判。
- **样式链读不到的维度**：列「未判定」，不拿 Word 默认值凑问题数。这与页眉页脚、摘要检查的口径一致。

## 3. 与覆盖矩阵的关系

`docs/rule-notes/nku-2026-coverage-matrix.md` 把 M26-038 / M26-039 标为「候选检测 + 待确认」，理由包括部件边界、英文/中文 run 脚本、公式豁免和标题模式未定。本实现按上述第 2 节把这些不确定性逐项落到「不判 / 未判定 / 人工确认」，不擅自把 draft 升格为 approved，也不改矩阵的处理类型。

## 4. 样本与验证

13 份零依赖合成 docx 位于 `tests/fixtures/synthetic/back-matter/`，由 `generate.py` 生成并纳入
`verify_fixtures.py` 的逐部件重建与清单一致性核对。每个错例只偏离一个维度，并额外覆盖
「公式段行距豁免」与「附录 A/B 子标题」两个边界。样本为合成数据，不代表真实论文版式。
